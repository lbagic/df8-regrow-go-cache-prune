# ML module (Prompt G) — design decisions

Status: ✅ shipped 2026-07-13. All rules `beta: true` until a release of burn-in.

Scope: research/02 §9 targets + "most major AI/ML stuff" (session directive). 12 new rules under `category: ai`, 2 new tool queries.

## Decisions

### 1. HF hub: filesystem walker, not the `hf` CLI — deviation from the plan prompt

Prompt G said "delete via CLI". Rejected after looking at the ground truth:

- **Enumeration**: the CLI is usually venv-bound — the machine with 100GB in `~/.cache/huggingface` frequently has no `hf`/`huggingface-cli` on PATH (it's a pip package). Tool-missing = rule-does-not-apply would hide the biggest §9 target. The cache layout (`models--org--name/{blobs,snapshots,refs}`) is documented and stable; `tool_hf.go` walks it directly. Env resolution mirrors huggingface_hub: `HF_HUB_CACHE` > `HUGGINGFACE_HUB_CACHE` > `$HF_HOME/hub` > default.
- **Deletion**: HF's cache has **no DB and no cross-repo blob sharing** — snapshots symlink into the *sibling* `blobs/` dir. Trashing the whole repo dir is exactly what `hf cache rm` does, minus the undo. Invariant 4 (steward commands) targets stores a tool must GC (ollama, docker, simctl); HF hub is not one. Trash-not-rm wins: undoable, no CLI version fragmentation (`scan-cache`/`delete-cache` vs `hf cache ls/rm` churn across huggingface_hub 0.x→1.0).
- **Dedup-aware sizes** for free: `DirSize` counts physical blocks and doesn't follow symlinks, so a blob shared by N snapshots of one repo counts once.
- **Last-used** = max atime/mtime over snapshot files, Stat'd *through* the symlinks (blob answers) — same signal scan-cache calls `last_accessed`. `atime()` helper is build-tagged darwin/linux/other.
- Granularity: per-repo, not per-revision. Per-revision cleanup ("keep main, drop old revs") is a later extension; item identity supports it whenever a producer shows up.

### 2. Ollama: manifest-store walker for scan, `ollama rm` for delete

- `ollama list` needs the server running — a stopped Ollama.app would hide 40GB. `tool_ollama.go` reads `$OLLAMA_MODELS`/`~/.ollama/models/manifests/<registry>/<ns>/<model>/<tag>` (OCI-style JSON) directly. Corrupt manifests are skipped, not fatal.
- Deletion stays native (`ollama rm {arg}`): blobs are refcounted **across** models; only the steward may GC. If the server is down the executor fails loudly — noted in the rule.
- **Exclusive-bytes sizing** (research §15 "report du actual not logical; warn shared blobs"): `Item.Bytes` = blobs referenced by no other model — what `ollama rm` actually frees. Shared bytes surface in the label (`llama3:latest (+274.0 MB shared)`). A fully-shared model honestly shows ~0 B freed.
- Names rendered the way `ollama rm` accepts and `ollama list` displays: default registry+namespace stripped, `hf.co/org/model:Q4` kept in full.
- Last-used = manifest mtime (pull/update time; ollama does not persist last-run).

### 3. Models are `caution`, not research table's "Safe"

Research §9 marks HF/Ollama "Safe" in the *deletability* sense (nothing breaks, re-download exists). regrow's `safe` means **pre-selected for auto-clean** — a cleaner whose default proposal is "delete all your LLMs" is hostile, and `ollama create` customs aren't re-pullable at all. Caution = review-and-select, per-item rows make the review cheap. Same call as sim-devices in Prompt E.

### 4. One discovery rule for SD-ecosystem model libraries

ComfyUI, SD-WebUI/Forge, Fooocus all share the `models/checkpoints` layout → one rule (`comfyui-sd-models`): discover root `~`, name `models`, marker `checkpoints` (markers Stat, so a dir marker works). Surface-only per invariant — false positives are harmless (report-only) and true positives are exactly the "often irreplaceable" library. YAML footgun found: bare `~` in a YAML list is null — must quote `"~"`.

### 5. Fixture items carry `path`

`FixtureItem` gained `path` (rule path syntax, `~` = fixture home) so tool-query rules whose items are trashed by path (hf-hub) can golden-test trash actions. `fakeQuery` expands via `host.ExpandPath`.

### 6. Catalog additions beyond the prompt's four

hf-datasets (caution — regen is *compute*, hours of re-tokenizing), hf-xet (safe chunk cache), torch-hub, whisper, llama.cpp (`-hf` download cache, `~/Library/Caches/llama.cpp` on darwin), keras (only `models/`+`datasets/` subdirs — `keras.json` config stays), gpt4all (per-model `*.gguf` glob; localdocs DB excluded), wandb cache (safe; offline runs live in project dirs, not the cache). Skipped: vLLM (barely runs on macOS), Jan (path churn, unverified), MLX (uses HF hub — already covered). Claude Code dirs stay with Prompt H (hero-bug scanner).

## Verification

- Unit: walker tests on synthetic layouts (dedup size counted once; exclusive/shared blob split; name decoding incl. `hf.co` registry; env overrides; corrupt-manifest skip).
- Golden: all 12 rules (per-repo trash, `ollama rm` per item, surface-only skip).
- Live: this machine has zero ML caches (verified — honest zeros); end-to-end proven via synthetic caches + `HF_HUB_CACHE`/`OLLAMA_MODELS` overrides: scan shows per-model rows with keys/last-used/shared-annotation, `regrow plan hf-hub/model/meta-llama/Llama-3-8B ollama-models/llama3:latest` produces one trash + one native action.
